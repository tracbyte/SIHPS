## 📂 Folder Structure & Columns

Each yearly folder contains Excel and PDF versions (standard and detailed) for both hardware and software problem statements. Spreadsheets utilize a strict column framework sorted **alphabetically by theme**:

| Column Name | Description |
|---|---|
| **Organization** | The ministry, PSU, or organization that submitted the problem |
| **Problem Statement** | Full title of the problem statement |
| **Background** | Context on the real-world problem |
| **Description** | Detailed explanation of what the solution needs to do |
| **Expected Solution** | The specific deliverables/capabilities expected |
| **Category** | `Hardware` or `Software` |
| **Ps Number** | Official SIH problem statement number (e.g., `SIHxx001`) |
| **Theme** | The SIH category it falls under (e.g., Smart Automation) |

# 🤝 Contributing to SIHPS

Contributions are welcome to keep this dataset accurate and up-to-date for future participants.

### 📌 Ground Rules
1. **Keep Headers Identical:** Do not modify or rearrange column headers (`Organization`, `Problem Statement`, `Background`, `Description`, `Expected Solution`, `Category`, `Ps Number`, `Theme`).
2. **Sorting:** Always sort rows alphabetically by the `Theme` column before submitting.
3. **Missing Data:** Leave cells completely blank if data is missing on the official portal; do not guess parameters or use artificial fillers.

### 🛠️ Contribution Workflow
1. **Fork** the repository and create a unique feature branch:
   ```bash
   git checkout -b feature/update-data
   ```
2. Add or update your files inside the appropriate `SIHPSyyyy` folder.
3. Save and commit your changes locally:
   ```bash
   git commit -m "docs: add verified statements"
   ```
4. Push your branch up to your personal fork and open a **Pull Request** against our `main` branch.
